# 05 - 面板驱动（`xiaomi,umi-panel`）

本仓库原先只有 `simple-framebuffer`（ABL 留下的 cont-splash），Linux 下没有
真正的面板驱动。这里补一份**主线风格**的 DRM panel 驱动，来自
[colorgarden/umi-mainline](https://github.com/colorgarden/umi-mainline)，
已在小米 10（umi / SM8250 / **CSOT（华星光电）`j2_mp_42_02_0b`** 面板）上实测
跑通：1080×2340 命令模式 + DSC 1.1、`bl_ctrl_dcs` 背光、亮度 1..2047、
熄屏再亮、面板级 repower。

## 文件

| 路径 | 作用 |
|---|---|
| `patch/kernel/archive/sm8250-6.18/0001-drm-panel-xiaomi-umi.patch` | 内核补丁：`drivers/gpu/drm/panel/panel-xiaomi-umi.c` + Kconfig/Makefile |
| `patch/kernel/archive/sm8250-6.18/dt/xiaomi-umi-panels.dtsi` | 面板数据（时序 / DCS 序列 / panel-id），从原厂 DTB 生成 |
| `patch/kernel/archive/sm8250-6.18/dt/sm8250-xiaomi-umi-common.dtsi` | 打开 `&mdss` / `&mdss_dsi0` / `&mdss_dsi0_phy` 并 include 上面的 dtsi |

## 内核选项

```
CONFIG_DRM=y
CONFIG_DRM_MSM=y
CONFIG_DRM_MSM_DSI=y
CONFIG_DRM_MSM_DSI_7NM_PHY=y
CONFIG_DRM_PANEL_XIAOMI_UMI=y
```

`DRM_MSM` 会被依赖悄悄降级成 `=m`（例如 `QCOM_OCMEM=m`），要显式
`# CONFIG_QCOM_OCMEM is not set`。

## 换面板

驱动完全数据驱动，`xiaomi-umi-panels.dtsi` 是本机这块 **CSOT `j2_mp_42_02_0b`**
的数据（时序 + 652 字节 on 序列 + panel-id）。umi 出厂还有另外 21 个变体
（华星 `42` / 三星 `38` / …），换机器要用生成器从原厂 DTB 重新导出这一份
（生成器读的是原厂 dtbo 反编译出来的面板 dts，没放进本 PR；需要的话我可以
单独提）。驱动不用改。

## 已知问题

- DSC + cmd mode 在 msm 上有已知 tearing 报告
  ([msm#42](https://gitlab.freedesktop.org/drm/msm/-/issues/42))。
- **偶发开机黑屏**：面板 IC 没接住 on 序列。驱动带救援开关，重发 652 字节
  on 序列，不必重启：

  ```sh
  echo 1 > /sys/devices/platform/soc@0/ae00000.display-subsystem/ae94000.dsi/ae94000.dsi.0/repower
  ```

- 触摸不含在本 PR 内（ST FTS，见 umi-mainline 的 `docs/TOUCH.md`：缺的是
  PM8150B GPIO5 的 boost 电源）。
